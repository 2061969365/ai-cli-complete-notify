# Webhook 内容与诊断修复设计

## 目标

`2.14.0` 修复 Webhook 测试与真实提醒表现不一致的问题：钉钉自定义关键词只在用户手动填写测试内容时命中，真实任务因缺少关键词而被拒绝；飞书卡片在未生成 AI 摘要且没有原文输出时丢失任务内容；Webhook 内部错误没有传递到测试面板。本次只调整 Webhook 内容组装、测试默认文案和错误返回，不改变各 CLI 的完成判断、Hook/Watch、去重或其他通知通道。

## 统一标识

- 所有 Webhook 平台统一使用固定标识 `AI提醒`，不增加钉钉专属配置。
- 飞书、钉钉、企业微信和通用 Webhook 的测试与真实通知都必须包含该标识。
- 组装消息时检查现有内容，确保 `AI提醒` 至少出现一次且不重复注入。
- 测试提醒的默认内容改为包含 `AI提醒`，让用户看到的测试输入与实际安全关键词一致。
- 桌面、声音、邮件、Telegram 和 Gotify 的标题与正文保持不变。

## 飞书卡片正文

- AI 摘要成功时继续显示 `AI 摘要`，保持现有摘要优先和原文开关行为。
- AI 摘要未使用、没有可展示原文但存在任务内容时，卡片显示 `任务内容`，测试提醒不得再出现空正文。
- 有原文输出时继续使用现有 `输出内容` 或 `原文` 区块，避免重复展示泛化的任务描述。
- 自定义卡片模板中的 `${TASK_INFO}` 继续生效；默认模板缺少该占位符时按上述规则注入正文。

## 错误诊断

- `notifyWebhook` 汇总每个失败请求的 provider、HTTP 状态或平台返回原因，并设置顶层 `error`。
- 多个 Webhook 同时失败时合并简短原因；部分或全部失败仍保持现有 `ok` 语义。
- 错误信息不得包含 Webhook URL、`access_token`、密钥或完整响应对象。
- CLI 与测试面板沿用现有输出逻辑，获得顶层错误后显示例如 `FAIL webhook: dingtalk: keywords not in content`。

## 版本与文档

- `package.json`、`package-lock.json`、Tauri 配置、Cargo 清单与锁文件统一更新为 `2.14.0`。
- `.env.example` 和五份 README 说明 Webhook 固定标识及钉钉机器人应使用 `AI提醒` 作为自定义关键词。
- 五份 README 增加 `2.14.0` 版本历史，说明统一标识、飞书正文回退与失败详情展示。

## 测试

- 钉钉测试和真实消息在任务内容不含关键词时仍自动包含一次 `AI提醒`。
- 任务内容已经包含 `AI提醒` 时不重复注入。
- 飞书卡片在无摘要、无原文时显示测试任务内容。
- 飞书摘要成功、摘要失败、原文显示开关和自定义模板行为保持通过。
- 钉钉、飞书及 HTTP 失败返回顶层脱敏错误，CLI 能输出具体原因。
- 全量 Node 测试、前端构建和 `cargo check` 通过。
